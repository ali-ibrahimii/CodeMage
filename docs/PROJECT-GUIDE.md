# راهنمای کامل پروژه‌ی CodeMage

این سند **همه‌ی فایل‌ها، ساختار و شیوه‌ی کار سایت** را توضیح می‌دهد. اگر می‌خواهی قابلیتی اضافه کنی یا باگی رفع کنی، از همین‌جا شروع کن.

---

## ۱. سایت چیست و چطور کار می‌کند؟

CodeMage یک **فضای فارسی یادگیری** است: درس‌های برنامه‌نویسی، ریاضی و فیزیک + نقشه‌ی راه‌های آماده + پنل مدیریت محتوا.

سه لایه‌ی اصلی دارد:

1. **صفحه‌های عمومی** (`app/(site)`) — خانه، درس‌ها، نقشه‌ی راه‌ها، درباره ما. این صفحه‌ها سمت سرور (Server Component) رندر می‌شوند.
2. **پنل مدیریت** (`app/dashboard`) — ساخت و ویرایش موضوع/فصل/درس و متن‌های سایت. با Supabase Auth محافظت می‌شود.
3. **لایه‌ی داده** (`lib/content.ts` + `lib/supabase.ts`) — هر صفحه داده‌اش را از این لایه می‌گیرد. اگر Supabase وصل باشد از دیتابیس می‌خواند؛ اگر نه، **محتوای نمایشی** (`DEMO_*` در `lib/content.ts`) را نشان می‌دهد. به همین دلیل سایت بدون هیچ تنظیمی هم بالا می‌آید.

**جریان یک درخواست:**

```
مرورگر → Next.js (روت‌ها در app/) → lib/content.ts → Supabase (یا محتوای نمایشی)
                                        ↓
                        lib/markdown.ts + lib/diagram.ts (رندر متن، شکل، فرمول)
                                        ↓
                              HTML آماده در صفحه‌ی درس
```

## ۵. سیستم محتوا (Markdown + شکل + فرمول)

محتوای هر درس یک رشته‌ی Markdown فارسی است. رندر آن را `lib/markdown.ts` انجام می‌دهد (نه کتابخانه‌ی خارجی) تا همان چیزی که نویسنده می‌نویسد دقیقاً در سایت و پیش‌نمایش پنل دیده شود.

**قابلیت‌ها:**

- تیتر `#` تا `######`، پررنگ `**…**`، ایتالیک `*…*`
- فهرست شماره‌دار (`1.` یا `۱.`) با ادامه‌ی شماره در خط‌های خالی و فهرست نقطه‌ای با تودرتو
- کادر نکته `> **نکته:** …`
- کد سه‌بک‌تیکی با نام زبان (در تب «نمونه‌کدها» هم جمع می‌شوند)
- **عکس**: `![توضیح](/media/x.png)` — تنها در یک خط → `<figure>` با توضیح؛ داخل متن → `<img>`
- **فرمول**: `$x^2 + 3x_1$` داخل متن و `$$\frac{1}{2}$$` جداگانه؛ توان `^`، زیرنویس `_`، کسر `\frac{a}{b}`، جذر `\sqrt{x}` و نمادهایی مثل `\times \to \le \pi \int`
- **شکل**: فنس ` ```diagram ` با سه نوع:
  - `flow` — جعبه و فلش از راست به چپ؛ هر خط: `قدم اول|توضیح -> قدم دوم -> قدم سوم`
  - `steps` — فهرست شماره‌دار عمودی؛ هر خط: `عنوان | توضیح`
  - `plot` — نمودار تابع روی محورهای مختصات؛ خطوط `y = x^2 - 4` و تنظیمات `domain:` / `range:` / `title:`

شکل‌ها در `lib/diagram.ts` و به‌صورت **SVG** ساخته می‌شوند (بدون وابستگی خارجی). برای `plot` یک مفسر ریاضی کوچک (`evaluateExpression`) عبارت‌ها را با `x` محاسبه می‌کند (توان، پرانتز، `sin`، `cos`، `sqrt`، `pi` و …).

## ۶. سیستم نقشه‌ی راه

`lib/roadmaps.ts` شامل نقشه‌ی راه‌های دست‌نویس است؛ هر کدام:

- `stages[]` — مراحل (با هدف و مدت)
- هر مرحله `steps[]` — گام‌ها با `skills` (مهارت‌ها) و `lesson` اختیاری (لینک به درس واقعی سایت)
- `aliases[]` — نام‌های جایگزین برای جست‌وجو (فارسی و انگلیسی)

**جست‌وجوی هوشمند** (`RoadmapSearch.tsx`):

1. هنگام تایپ، پیشنهادها با امتیاز نمایش داده می‌شوند (`matchRoadmaps`).
2. اگر عبارت **دقیقاً** نام یک مسیر یا نام مستعارش باشد، پس از مکث کوتاه **خودکار** به صفحه‌ی آن مسیر می‌رود.
3. Enter همیشه به بهترین تطبیق می‌رود؛ کلیدهای جهت‌دار پیشنهادها را انتخاب می‌کنند.
4. نرمال‌سازی متن (`normalizeText`) تفاوت «ي/ی»، «ك/ک» و نیم‌فاصله را حذف می‌کند تا «جاوا اسکریپت» و «جاوااسکریپت» یکی باشند.

برای افزودن مسیر جدید، کافی است رکوردی به `ROADMAPS` اضافه کنی؛ صفحه‌ها خودکار کارت و جزئیاتش را می‌سازند.

## ۷. دیتابیس (Supabase)

اختیاری است؛ ساختار در `supabase/schema.sql`:

```
subjects (موضوع: C، پایتون، ریاضی…)
  └── chapters (سرفصل)
        └── lessons (درس: متن Markdown)
              └── exercises (تمرین)
profiles                ← کاربران و نقش‌ها (admin / editor / reader)
tags                    ← برچسب‌ها
site_settings           ← متن‌های صفحه‌ی اصلی (نام سایت، هیرو، خبرنامه)
lesson_progress/notes   ← پیشرفت و یادداشت کاربران
newsletter_subscribers  ← ایمیل‌های خبرنامه
```

- نمای `v_subject_outline` شمارش فصل/درس/دقیقه‌ی هر موضوع را می‌دهد.
- نوشتن فقط با نقش `admin` (سیاست RLS). اپلیکیشن هرگز کلید `service_role` استفاده نمی‌کند.
- `supabase/seed.sql` داده‌ی نمونه‌ی C / ریاضی / فیزیک را می‌سازد.

**متغیرهای محیطی** (`.env.local`):

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
```

اگر ست نشوند، `lib/supabase.ts` حالت `hasSupabaseConfig = false` را اعلام می‌کند و سایت با محتوای نمایشیِ `lib/content.ts` کار می‌کند.

## ۸. پنل مدیریت (`/dashboard`)

- بدون Supabase: صفحه‌ی اتصال + نمونه‌ی فقط‌خواندنی از محتوای نمایشی.
- با Supabase: ورود با ایمیل نقش `admin`.
- بخش‌ها: نمای کلی (آمار)، موضوع‌ها (ساخت/ویرایش)، فصل‌ها، مدیریت درس‌ها (فیلتر/جست‌وجو/صفحه‌بندی)، ظاهر و متن سایت.
- ویرایشگر درس (`MarkdownField.tsx`) همان رندر `lib/markdown.ts` را در تب پیش‌نمایش نشان می‌دهد.
- فهرست‌ها با `readAllRows` دسته‌ای خوانده می‌شوند تا سقف پاسخ Supabase باعث حذف بی‌صدای محتوا نشود.

## ۹. تست‌ها

```bash
corepack pnpm test:ui                 # همه‌ی تست‌ها (نیاز به chromium)
corepack pnpm exec playwright test tests/markdown.spec.ts   # فقط تست‌های واحد
```

- `markdown.spec.ts` و `roadmaps.spec.ts` **واحد** هستند (بدون مرورگر).
- `layout.spec.ts` و بخش‌های UI بقیه به chromium نیاز دارند (`corepack pnpm exec playwright install chromium`).
- تست‌های dashboard-auth با متغیر `DASHBOARD_AUTH_TESTS=1` و کلیدهای ساختگی Supabase اجرا می‌شوند (راهنما در README).
