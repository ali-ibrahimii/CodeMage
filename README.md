# CodeMage

یک فضای فارسی برای یادگیری برنامه‌نویسی، ریاضی و علوم؛ با فهرست موضوع‌ها، مسیرهای آموزشی و پنل مدیریت محتوا.

## شروع سریع

```bash
corepack pnpm install
corepack pnpm dev
```

سایت به‌صورت پیش‌فرض با محتوای نمایشی بالا می‌آید. برای ذخیره و انتشار واقعی درس‌ها، یک پروژه‌ی Supabase متصل کن.

## راه‌اندازی Supabase

۱. در ریشه‌ی پروژه فایلی به نام `.env.local` بساز و مقادیر پروژه را قرار بده:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
```

کلید عمومی `publishable` یا `anon` را استفاده کن؛ **هرگز** `service_role` را در متغیر `NEXT_PUBLIC_*` قرار نده.

۲. در Supabase → SQL Editor فایل‌ها را به‌ترتیب اجرا کن:

- `supabase/schema.sql`
- `supabase/seed.sql` (اختیاری؛ محتوای نمونه‌ی زبان C، ریاضی و فیزیک را اضافه می‌کند)

۳. در Supabase → Authentication → Users یک کاربر بساز و حساب را تأیید کن. سپس در SQL Editor نقش همان حساب را مدیر کن:

```sql
update public.profiles
set role = 'admin'
where email = 'your@email.com';
```

برای بررسی دسترسی:

```sql
select public.is_admin();
```

۴. سرور توسعه را دوباره اجرا کن و به مسیر `/dashboard` برو. با همان ایمیل و گذرواژه وارد می‌شوی.

## پنل مدیریت

داشبورد از هدر، منوی عمومی و فوتر سایت جداست. **نمای کلی** فقط آمار و وضعیت انتشار را نشان می‌دهد؛ فهرست‌ها و فرم ساخت درس در این صفحه نمایش داده نمی‌شوند.

- آمار را بر اساس موضوع و زمان آخرین ویرایش فیلتر کن؛ بازدیدها مجموع بازدید کل عمر درس‌های انتخابی هستند، نه بازدید یک بازه‌ی زمانی.
- در **موضوع‌ها** با دکمه‌ی «موضوع جدید» دسته‌بندی تازه بساز (مثلاً «زبان پایتون») و با «ویرایش موضوع» عنوان، نامک، توضیح، آیکون، رنگ، نوع، سطح، ترتیب و وضعیت انتشارش را تغییر بده. جست‌وجو، وضعیت انتشار، مرتب‌سازی و صفحه‌بندی مستقل هم در دسترس است؛ از هر ردیف به درس‌ها یا فصل‌های همان موضوع برو. در **فصل‌ها** هم همان فیلترها وجود دارد.
- در **مدیریت درس‌ها** بر اساس موضوع، فصل، وضعیت و ویژه‌بودن فیلتر کن؛ مرتب‌سازی و انتخاب ۱۰، ۲۵ یا ۵۰ نتیجه در صفحه هم وجود دارد. تغییر فیلتر، شماره‌ی صفحه را به ابتدا برمی‌گرداند.
- ویرایشگر فقط با انتخاب «درس جدید» یا «ویرایش درس» باز می‌شود. بازگشت به فهرست، فیلترهای قبلی را حفظ می‌کند.
- تنظیمات سایت را بر اساس بخش مورد نظر محدود کن.

فهرست‌های مدیریتی به‌صورت دسته‌ای خوانده می‌شوند تا محدودیت پاسخ Supabase باعث حذف بی‌صدای محتوا نشود. محتوای کامل Markdown فقط هنگام بازکردن ویرایشگر دریافت می‌شود.

اگر Supabase تنظیم نشده باشد، از صفحه‌ی اتصال می‌توان **نمونه‌ی فقط‌خواندنی** داشبورد را باز کرد. این حالت از محتوای نمایشی موجود استفاده می‌کند، آمار واقعی ندارد و هیچ نوشتنی در دیتابیس انجام نمی‌دهد. با تنظیم Supabase، ورود با نقش مدیر همچنان الزامی است و حالت نمونه ارائه نمی‌شود.

از بخش‌های مدیریت می‌توانی:

- درس جدید بسازی، پیش‌نویس نگه داری یا منتشر کنی؛
- عنوان، نامک، توضیح، زمان مطالعه و محتوای Markdown را ویرایش کنی؛
- درس‌ها را به موضوع و فصل متصل کنی یا هنگام ساخت درس، موضوع و فصل تازه بسازی؛
- درس را به‌عنوان محتوای ویژه‌ی صفحه‌ی اصلی علامت‌گذاری کنی؛
- نام و شعار سایت، متن هیرو، دکمه‌ها، بخش دعوت به یادگیری و خبرنامه را ویرایش کنی.

### نقشه‌ی راه‌ها (Roadmaps)

در `/learning-paths` علاوه بر مسیرهای ساخته‌شده از درس‌ها، **نقشه‌ی راه‌های آماده** برای فرانت‌اند، بک‌اند، زبان‌های برنامه‌نویسی (پایتون، جاوااسکریپت، C) و علوم (ریاضی، فیزیک) وجود دارد. هر نقشه به مراحل و گام‌های مشخص با مهارت‌ها و لینک درس‌های مرتبط تقسیم شده است.

- در کادر جست‌وجوی همان صفحه، نام زبان یا موضوع را بنویس (مثلاً «پایتون»، «فرانت‌اند»، «python»، «فیزیک»)؛ با Enter یا انتخاب پیشنهاد، **خودکار** به صفحه‌ی نقشه‌ی راه همان موضوع می‌روی. اگر عبارت دقیقاً نام یک مسیر باشد، هنگام تایپ هم مستقیم می‌رود.
- در جست‌وجوی `/tutorials` هم اگر عبارت با نقشه‌ی راهی جور باشد، کارت پیشنهادی «نقشه‌ی راه» بالای نتایج نمایش داده می‌شود.
- نقشه‌ها در `lib/roadmaps.ts` تعریف می‌شوند؛ برای افزودن مسیر تازه فقط کافی است یک رکورد به آرایه‌ی `ROADMAPS` اضافه کنی.

### نوشتن محتوا و شماره‌گذاری

محتوای درس Markdown است و ویرایشگر درس یک نوار ابزار و تب **پیش‌نمایش** دارد؛ هرچه می‌نویسی همان‌جا همان‌طور که خواننده می‌بیند نمایش داده می‌شود.

| هدف | چه بنویسی |
| --- | --- |
| تیتر بخش | `## عنوان بخش` |
| شماره‌گذاری بخش‌ها | `## ۱. عنوان بخش` یا دکمه‌ی «شماره‌گذاری تیترها» تا خودش ۱، ۲، ۳ بگذارد |
| فهرست شماره‌دار (مرحله‌ها) | `1. قدم اول` و `2. قدم دوم` — عدد فارسی `۱.` هم کار می‌کند |
| زیرمجموعه‌ی فهرست | سه فاصله قبل از `-` یا `1.` |
| فهرست نقطه‌ای | `- مورد اول` |
| متن پررنگ | `**نکته‌ی مهم**` |
| کادر نکته | `> **نکته:** ...` |
| مثال کد | سه بک‌تیک، نام زبان (`python`, `c`, `js`, `text`)، کد، سه بک‌تیک |
| شکل گردش‌کار (جعبه و فلش، راست‌به‌چپ) | ```` ```diagram flow ```` سپس هر خط: `قدم اول -> قدم دوم -> قدم سوم` (برای زیرنویس: `عنوان|توضیح`) |
| شکل مراحل (راهنمای شماره‌دار عمودی) | ```` ```diagram steps ```` سپس هر خط: `عنوان | توضیح` |
| نمودار تابع (ریاضی/فیزیک) | ```` ```diagram plot ```` سپس `y = x^2 - 4` و اختیاری `domain: -4..4` یا `range: -5..5` و `title: ...` |
| فرمول داخل متن | `$x^2 + 3x_1$` — با `^` توان، با `_` زیرنویس، `\frac{a}{b}` کسر و `\sqrt{x}` جذر |
| فرمول جداگانه | `$$\lim_{x \to 2} (3x + 1) = 7$$` |
| عکس | `![توضیح عکس](/media/pic.png)` — اگر تنها در یک خط باشد با توضیح زیرش نمایش داده می‌شود |

نکته‌های شکل و فرمول:

- شکل‌های `diagram` به‌صورت SVG و بدون هیچ کتابخانه‌ی خارجی رندر می‌شوند و در همان پیش‌نمایش ویرایشگر دیده می‌شوند.
- در `plot` می‌توانی چند تابع هم‌زمان بنویسی (هر خط `y = ...`) و از توابع `sin`، `cos`، `sqrt`، `abs`، `ln` و ثابت‌های `pi` و `e` استفاده کنی.
- نمادهای پرکاربرد LaTeX مثل `\times`، `\to`، `\le`، `\pi` و `\int` به نماد فارسی‌خوان تبدیل می‌شوند.

نکته‌های شماره‌گذاری:

- شماره‌ها در سایت با رقم فارسی (۱، ۲، ۳) نمایش داده می‌شوند؛ خودت می‌توانی فارسی یا لاتین بنویسی.
- فهرست شماره‌دار حتی با یک خط خالی بین موردها هم شماره را ادامه می‌دهد؛ با یک پاراگراف وسط، شماره‌گذاری از نو شروع می‌شود.
- اگر خطی مثل «مراحل:» قبل از فهرست بنویسی، فهرست همچنان شماره‌دار رندر می‌شود.
- اعداد اعشاری متن (مثل `3.14`) به فهرست تبدیل نمی‌شوند.

دسترسی نوشتن با Supabase Auth و سیاست‌های RLS در `supabase/schema.sql` محافظت می‌شود؛ اپلیکیشن از کلید محرمانه‌ی مدیر استفاده نمی‌کند.

## بررسی ظاهر و رفع استایل قدیمی

فونت متغیر وزیرمتن از `public/fonts` سرو می‌شود؛ نمایش متن فارسی نیازی به نصب فونت روی دستگاه یا اتصال به سرویس فونت خارجی ندارد. مجوز OFL فونت کنار فایل‌های آن قرار دارد.

اگر بعد از دریافت تغییرات، پس‌زمینه‌ی هیرو سفید است، متن‌های آن دیده نمی‌شوند یا محتوای صفحه به لبه‌ها چسبیده است، ابتدا سرور توسعه را با `Ctrl+C` متوقف کن و سپس در ریشه‌ی همین پروژه اجرا کن:

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm dev:clean
```

این فرمان فقط خروجی تولیدشده‌ی `.next` را پاک می‌کند و سرور توسعه را دوباره بالا می‌آورد؛ فایل‌های محتوا و تنظیمات محیطی حذف نمی‌شوند. سپس در مرورگر `Ctrl+Shift+R` بزن تا فایل CSS قبلی از کش خوانده نشود. این دستور را هم‌زمان با سرور در حال اجرا استفاده نکن.

### تست چیدمان

```bash
corepack pnpm exec playwright install chromium
corepack pnpm test:ui
```

تست‌ها بارگذاری استایل عمومی و فونت فارسی، فاصله‌ی محتوای صفحه از لبه‌ها، عدم اسکرول افقی در عرض‌های ۳۲۰ تا ۱۴۴۰، منوی موبایل/تبلت، جست‌وجوی راست‌به‌چپ، نمونه‌کد درس و حالت تاریک را بررسی می‌کنند. بهتر است تست‌ها با محتوای نمایشی (بدون متغیرهای Supabase) اجرا شوند. اگر سروری روی پورت ۳۰۰۰ اجرا شده باشد، همان نسخه بررسی می‌شود؛ برای تست خروجی انتشار، قبل از تست `corepack pnpm build` و سپس `corepack pnpm start` را اجرا کن.

### تست داشبورد با احراز هویت شبیه‌سازی‌شده

تست‌های عادی، پیش‌نمایش فقط‌خواندنی و چیدمان را پوشش می‌دهند. برای بررسی کتابخانه‌ی ۱۲۰۷ درسی، بارگذاری محتوای کامل فقط هنگام ویرایش، ذخیره و جلوگیری از ورود کاربر غیرمدیر، ابتدا سرور توسعه‌ی قبلی را متوقف کن و در یک ترمینال اجرا کن:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://dashboard-test.supabase.co \
NEXT_PUBLIC_SUPABASE_ANON_KEY=fake-public-test-key \
corepack pnpm dev --hostname 0.0.0.0
```

سپس در ترمینال دیگر:

```bash
DASHBOARD_AUTH_TESTS=1 corepack pnpm exec playwright test tests/dashboard-auth.spec.ts
```

تمام درخواست‌های Supabase مرورگر در این تست‌ها شبیه‌سازی می‌شوند؛ کلید بالا ساختگی است و به حساب یا دیتابیس واقعی نیاز نیست. پس از تست، سرور را متوقف و بدون این متغیرهای ساختگی دوباره اجرا کن.
